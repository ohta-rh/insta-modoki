# ADR-0001: 決定は ADR として docs/adr/ に記録する

- ステータス: 採用
- 日付: 2026-11-20
- 決定者: ユーザー
- 関連: [ADR-0002](0002-docs-as-okf-v0-3-bundle.md)

## 背景

開発はエージェントがセッションをまたいで進める。会話・commit メッセージ・計画にしかない決定は、次のセッションでは失われる。ユーザーの全体ルールは、決定を同じ変更の中で ADR に残すよう定めている。

## 決定

- アーキテクチャ・技術選定・横断ルールの決定は、決めたのがユーザーでもエージェントでも、`docs/adr/NNNN-kebab-title.md` に ADR として残す。
- ADR は、その決定を形にする変更と同じ commit に入れ、[一覧](./)に足す。
- 採用した ADR の決定は書き換えない。変えるときは新しい ADR で置き換え、古い ADR を `status: deprecated` と `superseded_by` にする。
- 書き方は [template.md](template.md) に従う。

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| ADR（採用） | 理由と却下した案が残る。エージェントが読める | 決定のたびに 1 ファイル書く |
| commit メッセージと issue だけ | 手間が少ない | 探せない。置き換えの関係が残らない |

## 結果

- 決定の理由を後から追える。同じ議論を繰り返さない。
- 決定の前に既存の ADR を読む。根拠なしに覆さない。
