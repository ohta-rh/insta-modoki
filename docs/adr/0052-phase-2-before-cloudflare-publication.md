# ADR-0052: マイルストーンの順番を M1 → M3（Phase 2 をローカルで）→ M2（Cloudflare で公開）→ M4 に変える

- ステータス: 採用
- 日付: 2026-11-22
- 決定者: ユーザー（「M3 をローカルで動くところから実装してほしい」「順番が劣後したので issue の構成変える必要あるなら変えといて」）
- 関連: 置き換える [ADR-0013](0013-four-milestones-local-mvp-then-cloudflare.md)、[ADR-0006](0006-first-milestone-runs-locally-on-docker-compose.md)、[ADR-0011](0011-deploy-to-cloudflare-free-tier-first.md)、[ADR-0017](0017-milestone-on-an-integration-branch-when-a-pr-is-requested.md)

## 背景

- ADR-0013 は、マイルストーンを M1 ローカルの MVP → M2 Cloudflare で招待制公開 → M3 Phase 2 → M4 Phase 3 の順に決め、期日を 2027-02-14・02-28・04-11・05-09 とした。
- 2026-11-22、M1 は統合ブランチ `m1/local-mvp`（PR #69）で全 EPIC の総合試験が PASS し、ユーザーのマージを待っている。
- M2 の PBI のうち #21（Cloudflare のリソース）、#29（製品名の承認）、#43（GitHub の OAuth アプリ）は、ユーザーにしかできない作業を含み、`blocked` が付いている。
- ユーザーは M3 をローカルで動くところから作るよう求め、M2 の順番が後になったと述べた。
- M3 の PBI は全てローカル（docker compose の Garage と wrangler・workerd）で作り、確かめられる。依存は M1 の #46 と M3 の中だけで、M2 の issue には依存していない（2026-11-22 に全 11 本の blocked by を確かめた）。

## 決定

- マイルストーンの中身は ADR-0013 のまま保ち、**順番を M1 → M3 → M2 → M4 にする**。期日は次のとおりにする。

| 順 | Milestone | 中身 | 期日 |
|---|---|---|---|
| 1 | M1: MVP がローカルで動く | 企画書の Phase 0（基盤）と MVP の 8 機能 | 2027-02-14 |
| 2 | M3: Phase 2 | ストーリー・発見・通知・保存。**ローカルで動き、確かめられる**ところまで | 2027-03-28 |
| 3 | M2: Cloudflare に招待制デモとして公開 | M1 と M3 の機能をまとめて公開する。名称の確定、Cloudflare のリソース、デプロイの自動化、招待制、GitHub OAuth、管理者による削除、本番のデモデータ | 2027-04-11 |
| 4 | M4: Phase 3 と成功指標 | DM・安全・PWA・縦型動画（任意）・成功指標の計測・紹介ページ | 2027-05-09 |

- マイルストーンの名前（番号）は変えない。issue の本文とドキュメントが名前で参照しているので、名前を変えると参照が切れる。順番は期日と、この ADR とマイルストーンの説明で示す。
- M3 の受け入れ条件は「ローカルで動く」で判定する。本番で動くことの確認は M2 の受け入れ条件に移す。M3 の中で本番でしか測れないもの（ADR-0050 の配信の本番の CPU 時間など）は、M2 のデプロイで確かめる。
- M3 は M1 の統合ブランチの上に積んだ統合ブランチ `m3/phase2` で進め、PR は `m1/local-mvp` を base にする（ADR-0017、積み重ねた PR）。PR #69 が `main` に入ると、GitHub が base を `main` に付け替える。

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| 順番を M1 → M3 → M2 → M4 にし、名前は変えない（採用） | ユーザーにしかできない作業を待たずに、機能を作り進められる。参照が切れない | 名前の番号と順番がずれ、読み手が戸惑いうる |
| マイルストーンの名前も付け替える（M2 ↔ M3） | 番号と順番が一致する | 全ての issue の本文とドキュメントの参照を書き換えることになり、取り違えが起きやすい |
| ADR-0013 の順番のまま、M2 を先に進める | 計画どおり | M2 はユーザーの作業（アカウント・支払い・名称の承認）を待つので、進められない |

## 結果

- M3 の 4 機能を、ユーザーの作業を待たずにローカルで作り、総合試験まで進められる。
- M2 は、M1 と M3 の機能をまとめて 1 度に公開する。本番での確認の範囲が広がる。
- マイルストーンの番号と実行の順番がずれる。マイルストーンの説明の先頭に、順番を書いて補う。
- 今後は、マイルストーンの順番と期日の変更を、この ADR を置き換える新しい ADR で記録する。
