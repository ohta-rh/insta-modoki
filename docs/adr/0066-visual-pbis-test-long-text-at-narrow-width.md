# ADR-0066: 見た目の PBI は、狭い画面で長い利用者の文字の配置を AC にする

- ステータス: 採用
- 日付: 2026-11-24
- 決定者: エージェント（委任された判断。Director が採番）
- 関連: [ADR-0004](0004-milestone-epic-pbi-with-dor-ac-dod.md)、[ADR-0005](0005-map-dependencies-for-parallel-work-at-filing.md)、[ADR-0056](0056-ui-follows-measured-web-reference-under-own-brand.md)、#118

## 背景

- #93（プロフィールの見た目）は AC が全て通っていたが、768px 未満で自己紹介の箱がアイコンの列に入り、空白のない長い 1 行の自己紹介で列が 941px まで広がって名前の行が潰れた。コードレビューまで見つからなかった（f492309 で修正）。
- AC が短い seed の文字だけで書かれており、`.claude/rules/issue-authoring.md` にも write-pbi の AC の観点にも、狭い画面で長い利用者の文字を入れる場面がなかった。

## 決定

- 見た目を変える PBI は、利用者が入れる文字（名前・表示名・自己紹介・キャプション・コメント）を、375px の画面で上限の長さ、または空白のない長い 1 行にしたとき、隣の要素の位置と自分の幅を確かめる AC を 1 つ以上持つ。確認方法は E2E の名前にする。
- 利用者の文字を出さない画面の PBI は、本文に対象外の理由を書く。
- 規則は `.claude/rules/issue-authoring.md` の「見た目の PBI」の節に置き、`scripts/issue-rules.test.ts` が節の存在を守る。

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| 規則と守るテストを足す（採用） | 起票の時点で AC に入り、消えたらテストが落ちる | 起票者が対象外かどうかを判断する |
| レビューの観点だけに足す | 起票は変わらない | 実装後に見つかるので手戻りが大きい |
| 全 PBI に一律で要求する | 抜けがない | 利用者の文字を出さない PBI に意味のない AC が入る |
| グローバルの write-pbi を変える | 他のリポジトリにも効く | このリポジトリの外で、範囲外 |

## 結果

- 見た目の PBI は、起票の時点で狭い画面の長い文字の AC を持つ。開いている #97・#100 には同じ観点を反映した（#100 は AC-10 を足し、#97 は文字を出さないので対象外と記した）。
- 閉じた PBI の画面への後追いの E2E は足さない。EPIC #87 の総合試験で長い文字の場面を見る。
- テストが守るのは節の見出しと 2 つの語だけで、AC が実際に書かれたかは起票時の確認（Director）に残る。
