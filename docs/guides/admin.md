# 管理者の手順

通報の機能（M4）より前に公開するので、問題のある投稿と利用者を消す手段は管理者の削除だけである（企画書 12 ページ R3、R4）。管理者は `users.role = 'admin'` の利用者で、権限は呼び出しのたびにこの列から判定する（画面や入力に何を付けても、管理者にはならない）。

## 管理者を作る

利用者がサインアップしたあとで、その利用者の `role` を `'admin'` にする。アプリに管理者を作る画面は無い。

* ローカル（`wrangler` の D1 のファイル。worktree の `.wrangler/state`）:

  ```bash
  pnpm exec wrangler d1 execute DB --local --command "UPDATE users SET role = 'admin' WHERE username = '<ユーザー名>'"
  ```

* 本番（Cloudflare の D1）: 同じ文を `--remote` で流す。DB の資格情報は持ち主だけが持つので、持ち主が流す。

  ```bash
  pnpm exec wrangler d1 execute DB --remote --command "UPDATE users SET role = 'admin' WHERE username = '<ユーザー名>'"
  ```

流したあと、その利用者は `/admin` を開ける（次のログインを待たない）。管理者を外すときは `'user'` に戻す。管理者が全員いなくなるのを防ぐため、アプリは管理者を削除できない（自分も、別の管理者も `FORBIDDEN`）。

## `/admin` でできること

* タブ「投稿」: 新しい順に 20 件ずつ。投稿者・キャプションの先頭 50 字・日時を見て、「削除」を押す。
* タブ「利用者」: 新しい登録順に 20 件ずつ。ユーザー名の前方一致で絞り込める。「削除」で利用者を消す。管理者の行には「削除」が無い。
* 「招待コードの管理」のリンクから `/admin/invites`（招待コードの発行と失効）へ移る。
* 管理者でない利用者が `/admin` を開くと「ページが見つかりません」になり（画面があることを知らせない）、ログインしていない人は `/accounts/login` へ移る。

## 削除は取り消せない

* 投稿を消すと、投稿・写真（メディア）・いいね・コメントの行と、保存してあった写真のファイルが全て消える。
* 利用者を消すと、その人の投稿・コメント・いいね・フォロー・セッション（以後ログインできない）・ストーリー・通知・保存・アイコンの画像のファイルが全て消える。他人の投稿に付いていたその人のいいね・コメント（返信を含む）の分だけ、その投稿の `like_count` と `comment_count` が減る。
* 元に戻す手段は無い。消す前に、投稿者・キャプション・ユーザー名をよく確かめる。
* ファイルの削除だけが失敗したときは、行は消えたままにして、失敗したファイルを `storage_orphans` に記録する。定期のジョブが後で消し直す。

## 確認のしかた

1. 「削除」を押すと確認の画面（`<dialog>`）が開く。対象の名前（「@ユーザー名 の投稿」「@ユーザー名」）が見出しに出る。
2. 「削除する」で実行、「キャンセル」または Esc で閉じる（何も消えない）。
3. 実行すると一覧からその行が消え、「… を削除しました」が出る。失敗したときは行が残り、赤い文字でサーバーの理由が出る。
4. 成功した削除は `admin_actions` に 1 行（誰が・何を・いつ）残り、対象を消したあとも残る。失敗した削除は記録しない。確かめるとき（ローカル）:

   ```bash
   pnpm exec wrangler d1 execute DB --local --command "SELECT admin_id, action, target_id, created_at FROM admin_actions ORDER BY created_at DESC LIMIT 10"
   ```
