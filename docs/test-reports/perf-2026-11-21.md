## 基準を割らないことの確認（AC-7）

使い捨ての branch には切り替えられないので、初期 JS を増やす変更（ランダムな約 270KB の文字列を `AppShellClient.tsx` から読み込む。commit しない）を入れてビルドし直し、`node scripts/perf/bundle.mjs` を流した。出力は次のとおりで、終了コードは 1。確かめた後に `git restore` と、足したファイルの削除で戻し、`git status` が空になることを確かめた。

```
bundle: initial js gzip=353273 limit=170000
perf: FAIL initialJsGzipBytes / 353273 > 170000
```

## 修正

| 項目 | 内容 |
|---|---|
| 割れた指標 | 初期 JS（`initialJsGzipBytes`）が 183,451 バイトで基準の 170,000 を超えた（初回の `bundle.mjs`: `perf: FAIL initialJsGzipBytes / 183451 > 170000`）。他の指標は初回から基準以内 |
| 原因 | クライアントのコンポーネント（`CommentForm`・`ImagePicker`・`CaptionField`・`PhotoList`・`CreatePostForm`・`EditProfileForm`）が、上限や文言の定数を zod を読み込む `model/schema.ts` から import していたため、zod（gzip で約 33KB の 1 チャンク）が全ての画面のブラウザに配られていた |
| 直した箇所 | 定数を zod の無い `model/limits.ts` に移し（comment・media-upload・post-create・profile の 4 slice）、`schema.ts` はそこから import して再 export する（既存の import は変わらない）。クライアントのコンポーネントは `limits.ts` から import する |
| 前後の値 | 初期 JS 183,451 → 150,208 バイト（33,243 バイト減）。修正は 1 日に収まった |
