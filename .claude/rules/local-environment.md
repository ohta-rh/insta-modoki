# Local environment — one shared compose stack, a slot per worktree (ADR-0006, ADR-0037)

Milestone 1 runs only on the developer machine with `docker compose`. The deploy target is
Cloudflare (ADR-0011), so local services stand in for Cloudflare ones. The DB is D1 (ADR-0019),
so compose has one service: Garage (`dxflrs/garage:v2.5.0`), S3-compatible storage standing in
for R2 (ADR-0021, ADR-0037). This rule fixes how worktrees share it.

## Shape

- **One compose project** named `insta-modoki` (fixed `name:` in `compose.yaml`), started from
  the main checkout, with the service `s3` (Garage; S3 API on host `127.0.0.1:3910`, web endpoint on `127.0.0.1:3912`).
- **The DB is D1**: wrangler keeps it as files in `<worktree>/.wrangler/state` (git-ignored), so
  it is already isolated per worktree and needs no slot name, only a reset at dispatch.
  Integration tests use `getPlatformProxy({ persist: false })` (in-memory D1).
- **Worktrees never start their own stack.** They run the app, unit/integration tests and
  Playwright on the host, pointed at the shared services through their slot's env file.
- **Only the Director** starts, stops, upgrades or resets the shared stack. Workers must not run
  `docker compose down`, `-v`, `restart`, or edit containers.

## Slots

The Director assigns each in-flight PBI a slot `N` in `1..4` (`0` = the main checkout):

| Resource | Slot `N` |
|---|---|
| App port | `3100 + N` (main = 3100; 3000 and 3001 are taken by other projects on this machine) |
| Database (D1) | `<worktree>/.wrangler/state` (files; no name) |
| Object storage bucket | `insta-s<N>` |
| Media origin (anonymous reads) | `http://insta-s<N>.web.localhost:3912` (Garage web endpoint; `S3_PUBLIC_BASE_URL` and `MEDIA_ORIGIN`). The S3 API on 3910 refuses anonymous GET and serves only signed PUT/HEAD/DELETE |
| Settings file | `<worktree>/.dev.vars` (read by wrangler), generated by the slot script; never committed. Includes `AUTH_PEPPER` and the S3 key, generated locally |

- Run these in the worktree (they write its `.dev.vars` and `.wrangler/state`):
  - `node scripts/slot.mjs prepare <N>` - create the bucket and the shared key if missing, enable website access on the bucket, write
    `.dev.vars`, apply `migrations/` with `wrangler d1 migrations apply DB --local` when it exists.
    Idempotent; keeps data and secrets.
  - `node scripts/slot.mjs reset <N>` - first stop the slot's app server (below), then delete
    `.wrangler/state`, empty the bucket, then prepare.
  - `node scripts/slot.mjs drop <N>` - first stop the slot's app server (below), then delete the
    bucket and `.wrangler/state`; keeps `.dev.vars`.
  - Stopping the app server (`drop` and `reset` only; `prepare` never touches processes): the
    listeners on port `3100 + N` and their parents whose command line names that port
    (`--port <port>`) are sent TERM with their children, KILL after 5 s. It prints
    `slot N のポート 310N のプロセスを M 個止めました`; if any survive it prints their PIDs and exits 1
    without deleting anything. Other ports are never touched (#83).
  - Exit codes: 0 ok, 1 stack down or command failed, 2 bad arguments. If the stack is down it
    says so; only the Director starts it.
- At dispatch the Director runs `prepare` (or `reset`); at cleanup, `drop`, so each PBI starts
  empty and leaves nothing behind.
- `scripts/slot.int.test.ts` runs only with `SLOT_INT=1` (verify skips it otherwise): run
  `SLOT_INT=1 PORT=3100 node scripts/verify.mjs` in the main checkout / CI only. It resets and
  drops two slots (default 0 and 4; `SLOT_INT_A`, `SLOT_INT_B`): run it only on slots no other
  worktree is using.
- Steps and troubleshooting: `docs/guides/local-development.md`.

## Changing the shared stack

A PBI that changes `compose.yaml` or service configuration affects every slot, so it runs alone
in its wave (`.claude/rules/issue-authoring.md` §3). The Director applies the change to the
running stack after that PBI is merged, before dispatching the next wave.
